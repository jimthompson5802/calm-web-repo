# Secrets Exposure Review — 2026-08-10

Scope: full working tree + full `git log --all` history of this repository
(`setup-keycloak-web`, branch `setup-keycloak-web`).

## Summary

**No secrets are currently leaked into the git repository or its history.**
The `.env`-based secret-handling design is sound: real credentials live only
in an untracked, gitignored `.env` file, and every place a secret is needed
(Docker Compose, the rendered Keycloak realm) sources it from there via
placeholders/environment substitution rather than hardcoding it.

## What was checked

1. `.gitignore` coverage vs. what's actually tracked (`git ls-files`).
2. Whether `.env` or any `.env.*` variant was ever committed, across all
   history (`git log --all --full-history -- .env .env.*`).
3. Full commit history for filenames matching secret/key/cert patterns
   (`*.pem`, `*.key`, `*.crt`, `*credential*`, `*secret*`, `*password*`, `.env*`).
4. Content grep of all currently tracked files for password/secret/token/API-key
   patterns and private-key headers.
5. `compose.yaml` and `infra/keycloak/calm-local-realm.template.json` for
   hardcoded credentials vs. environment/placeholder substitution.
6. `scripts/render-keycloak-realm.py`, which renders the realm template using
   values from `.env`.
7. Working-tree scan for `*.pem/*.key/*.crt/*.p12` files and their tracked status.
8. `git status --ignored` to confirm generated/secret-bearing paths are
   ignored, not merely absent.

## Findings

### 1. `.env` — real local secrets — never committed (OK)
- Present in the working tree with real-looking values (Keycloak admin
  password, OAuth2 proxy client secret, cookie secret, test user password).
- Confirmed **not tracked**: absent from `git ls-files`, absent from
  `git log --all --full-history -- .env`.
- Covered by `.gitignore` (`.env` and `.env.*`, with `.env.example` explicitly
  un-ignored).
- `git status --ignored` shows it correctly falling into the ignored bucket.

**No action needed.**

### 2. `.env.example` — template only (OK)
- The only `.env`-named file ever committed (added in `47686e0`).
- Contains placeholder values only (`change-me-admin-password`,
  `replace-with-a-generated-client-secret`, etc.), no real credentials.

**No action needed.**

### 3. `infra/keycloak/calm-local-realm.template.json` (OK)
- Contains `"secret": "__OAUTH2_PROXY_CLIENT_SECRET__"` — a placeholder token,
  substituted at render time by `scripts/render-keycloak-realm.py` using the
  value from the untracked `.env`.
- The **rendered output** (`infra/keycloak/import/calm-local-realm.json`,
  which would contain the real secret) is git-ignored
  (`infra/keycloak/import/` in `.gitignore`) and confirmed untracked.

**No action needed.**

### 4. `compose.yaml` (OK)
- References secrets only via `${OAUTH2_PROXY_CLIENT_SECRET}`,
  `${OAUTH2_PROXY_COOKIE_SECRET}`, `${KC_BOOTSTRAP_ADMIN_PASSWORD}`, etc. —
  standard Compose variable substitution, resolved from `.env` at runtime.
  No literal secret values in the file.

**No action needed.**

### 5. TLS materials (OK)
- `infra/nginx/certs/localhost.crt` and `localhost.key` exist locally
  (generated by `scripts/generate-local-certs.sh`) but the whole
  `infra/nginx/certs/` directory is git-ignored and untracked. These are
  self-signed localhost dev certs regardless, not sensitive production keys.

**No action needed.**

### 6. Broader content/history grep (OK)
- No AWS-style access keys, PEM/OpenSSH/PGP private key blocks, or other
  hardcoded API keys/tokens found anywhere in tracked file contents or in any
  historical commit's added files.

## Residual recommendations (defense-in-depth, optional)

These aren't fixes for a leak — none was found — but process hardening you
may want to consider:

1. **Rotate anyway before any public sharing of this repo/clone.** The values
   currently sitting in the local `.env` (e.g.
   `OAUTH2_PROXY_CLIENT_SECRET=o2GJimK7rn4Bs30f/i5iDaJCCH6AnIvgs09aSaEnoRs=`)
   are real-looking secrets on disk. They were never committed, but if this
   machine's `.env` is ever copied/zipped/shared alongside the repo (e.g. "zip
   up the project folder"), that would leak them outside of git entirely.
   Worth a reminder in the README/AGENTS.md not to bundle `.env` when sharing
   the project.
2. **Add a pre-commit secret scanner** (e.g. `gitleaks` or `detect-secrets`)
   to the repo (`Makefile`/CI) so any future accidental `.env` commit or
   hardcoded token is caught before it lands, rather than relying solely on
   `.gitignore` discipline.
3. **CI check**: add a `gitleaks detect --no-git -s .` (or similar) step to
   `.github/` workflows to catch regressions automatically.

No repository changes beyond this document have been made as part of this
review — the recommendations above are optional and pending your approval.
